# 0003 한글 수집 문장을 5문장으로 줄인다

## Context

- 한글 수집 문장은 9문장 218음절이었다.
- 음절의 52%는 새 필수 문맥형을 주지 않았다. 그런데 필수 문맥형의 절반은 한 번만 나왔다.
- 원인은 자연 문장의 자모 빈도다. 흔한 자모가 칸을 차지한다.
- 쌍자음은 이제 단자음에서 합성한다(`474e4a7`). 필수 문맥형은 129개에서 107개로 줄었다.
- 사용자는 적은 글자로 적당한 품질을 얻어야 한다. 더 좋은 품질은 선택 사항이다.

### 조건의 세 단계

| 단계        | 조건                          | 최소 음절 | 보장하는 것                     |
| ----------- | ----------------------------- | --------: | ------------------------------- |
| 생성 조건   | 모든 자모에 빌릴 그림이 있다  |        21 | 11,172자에 빠진 자모가 없다     |
| 필수 문맥형 | 필수 문맥형 107개를 직접 쓴다 |        69 | 필수 형태를 빌리지 않는다       |
| 학습 표본   | 배치 문맥 8개마다 음절 10개   |     약 79 | 간격과 크기를 안정적으로 배운다 |

조합 단계는 직접 쓴 형태가 없으면 다른 형태를 빌린다(`selectJamoSource`). 그래서 생성 조건은 필수 문맥형보다 훨씬 작다.

### 비교 시트

샘플 프로젝트에서 자모 그림을 일부만 남기고 같은 글자를 조합했다. 비율은 11,172자의 모든 자모 자리를 센 값이다.

| 안                                     | 음절 | 직접 쓴 자모 | 빌린 자모 | 합성 자모 |
| -------------------------------------- | ---: | -----------: | --------: | --------: |
| 모든 자모 한 번                        |   21 |        33.8% |     41.7% |     24.5% |
| 초성을 세로 배치와 가로 배치에 한 번씩 |   35 |        34.3% |     41.1% |     24.5% |
| 필수 문맥형 107개                      |   69 |        59.9% |     15.5% |     24.5% |
| 5문장 ("웬"이 있는 초안)               |  140 |        65.2% |     16.2% |     18.6% |
| 이전 9문장                             |  218 |        77.4% |     14.2% |      8.4% |

- 문장 단위의 인상은 모든 안이 비슷했다.
- 눈에 보이는 차이는 쌍자음과 겹받침에서 나왔다. 이전 9문장만 이 둘을 직접 쓴다.
- 샘플 프로젝트는 완전히 쓴 칸이 19개뿐이다. 모든 안이 같은 19칸에서 간격과 크기를 배웠다. 시트는 자모 그림의 차이만 보여 준다.

## Decision

### 문장

한글 수집 문장은 다음 5문장이다. 139음절이고 필수 문맥형 107개를 모두 준다.

1. 흐린 퇴근길 휴대폰에 육 년 만에 옛 친구의 문자가 왔다
2. 관람권 사진과 극장 출구 뒤편 벤치에서 십 분만 보자는 얘기였다
3. 저녁녘 택시가 모퉁이를 도니 스웨터에 코트를 걸친 친구가 왼손으로 노란 꽃을 흔들었다
4. 예전 그 시절이 꽤 좋았냐고 낮게 묻더니 바로 옆에서 내 표정을 살폈다
5. 뭐라 답할지 몰라 커피컵을 쥔 채 초콜릿 향만 맡으며 조용히 웃었다

### 문장의 규칙

문장을 바꿀 때 다음 규칙을 지킨다.

1. 문장은 필수 문맥형 107개를 모두 준다(`isRequiredPrompt`).
   - 초성 14개 × 초성 배치 4개(가, 고, 각, 곡 형태)
   - 받침 없는 중성 21개, 받침 있는 중성 16개
   - 종성 14개
2. 문장은 쌍자음과 겹받침을 필요로 하지 않는다. 조합 단계가 합성한다.
3. 문장은 실제 낱말로 쓴다. 사용자는 뜻이 없는 음절을 평소 글씨로 쓰지 않는다.
4. 문장은 문장 부호를 쓰지 않는다. 한글 문장의 문장 부호 칸은 아무것도 수집하지 않는다.
5. 새 필수 문맥형을 많이 주는 문장을 앞에 둔다. 사용자가 중간에 멈추면 앞 문장만 폰트에 들어간다.
6. 낱말 "웬"은 쓰지 않는다. 사용자는 받침 위의 좁은 자리에 `ㅞ`를 좁게 쓴다. "웨"의 `ㅞ`를 맞춰 넣은 결과가 더 좋았다.

### 필수 문맥형이 최소인 이유

- 한 음절은 초성을 하나만 준다. 필수 초성이 56개이므로 음절이 56개 필요하다.
- 필수 초성을 주는 음절은 필수 중성 13개를 담지 못한다. 음절이 13개 더 필요하다.
- 종성은 받침 있는 음절에 함께 들어간다. 종성은 음절 수를 늘리지 않는다.
- 그래서 최소는 69음절이다. 69음절은 뜻이 없는 음절의 목록으로만 가능하다.
- 실제 낱말로 쓴 문장은 조사와 어미가 필요하다. 그래서 139음절이다.
- 139음절 중 76음절이 필수 문맥형을 준다. 나머지 63음절은 조사, 어미, 낱말의 나머지 음절이다.

### 선택 그룹

더 좋은 품질은 기본 문장이 아니고 선택 그룹이 준다. 선택 그룹은 문장이 아니고 핵심 글자의 목록이다. 선택 그룹은 아직 구현하지 않았다.

| 그룹      | 좋아지는 것                           |
| --------- | ------------------------------------- |
| 쌍자음    | 합성 대신 쓴 그림을 쓴다              |
| 겹받침    | 합성 대신 쓴 그림을 쓴다              |
| 복합 모음 | 복합 모음의 간격과 크기 학습          |
| 다시 쓰기 | `bestDrawing`이 더 좋은 그림을 고른다 |

## Consequences

- 문장이 9개에서 5개로, 음절이 218개에서 139개로 준다.
- 문장 1에는 "옛"이 있다. 그래서 받침 있는 `ㅖ`는 사용자가 쓴 그림을 쓴다.
- 이전 문장으로 저장한 프로젝트는 맞지 않는다. 문장 기록은 `hangul-sentence-N`과 칸 번호로 저장되기 때문이다. 제품이 개발 단계이므로 이전 프로젝트를 변환하지 않는다.
- 샘플 프로젝트도 이전 문장으로 쓴 것이다. 새 문장으로 다시 써야 검증 도구가 맞는 결과를 낸다.
- 다음 값은 측정하지 않았다.
  - 학습 표본이 줄어든 영향. 샘플 프로젝트는 완전히 쓴 칸이 19개뿐이라 비교하지 못했다.
  - 다른 필기자의 결과. 샘플의 필기자는 한 명이다.
- 학습 표본이 10개보다 적은 배치 문맥이 3개 있다. 복합 모음은 받침 없는 음절 7개와 받침 있는 음절 5개다. `ㅗㅛ` 받침 있는 음절은 7개다. `trimmedMean`은 표본 10개부터 양 끝 값을 버린다.

## Alternatives

- 모든 자모를 한 번씩만 쓴다(21음절). 초성을 모든 배치에서 빌린다. 사용자가 품질이 부족하다고 판단했다.
- 초성을 세로 배치와 가로 배치에 한 번씩 쓴다(35음절). 같은 이유로 고르지 않았다.
- 9문장을 유지한다. 가장 길고, 필수 문맥형의 절반은 한 번만 나온다.
- 쌍자음을 필수로 둔다. 필수 초성이 20개 늘고 최소 음절이 89개가 된다.
