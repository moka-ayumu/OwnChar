# 0002 미리보기의 크기 다이얼

## Context

- 조합 설정은 `/edit`의 두 번째 탭에 있었다. 결과는 고정된 예시 카드에만 즉시 보였다. 사용자가 쓴 문장에는 전체를 다시 생성한 뒤에 보였다.
- 음절 안의 초성, 중성, 종성 크기를 고르게 하는 설정이 없었다. 기존 배율 3개(단일 초성, 모음, 받침)는 0.8로 정해도 자모 크기가 1.5%, −0.9%, 4.5%만 변했다. 뒤의 배치 규칙이 배율을 다시 흡수한다.
- 통째로 쓴 음절은 샘플 프로젝트에서 19개다. 대부분의 칸이 자모 하나만 수집한다. 그래서 그룹별 목표 크기를 필기에서 직접 학습할 표본이 없다.
- 조합된 글자에는 같은 구조 안의 편차가 있다. 1,596자에서 초성 7.3%, 중성 10.0%, 종성 10.7%, 글자 폭 12.4%다.

## Decision

- 조합 설정에 다이얼 4개를 추가한다: `initialNormalization`, `medialNormalization`, `finalNormalization`, `widthNormalization`. 값은 0에서 2까지이고 기본값은 1이다. 0에서는 다이얼이 없던 때와 출력이 같다. 1까지는 목표 쪽으로 당기는 양이 커진다. 1에서 목표에 맞춘다. 1을 넘으면 더 당기지 않고 한도를 값만큼 넓힌다. 2에서 한도는 두 배다.
- 그룹은 모음 종류 4가지와 받침 유무의 조합 8개다(`proportionContext`).
- 목표는 그룹의 평균이다. 그룹마다 40자를 다이얼 없이 배치해서 자모 크기와 글자 폭의 평균을 구한다(`learnSizeTargets`). 같은 자모끼리의 평균은 목표로 쓰지 않는다. 시험에서 그룹 안 편차가 거의 줄지 않았다.
- 다이얼은 `layoutSyllable`의 끝에서 적용한다. 배치 중간에 적용한 보정은 뒤의 규칙이 흡수했다. 초성 편차가 7.3%에서 변하지 않았다.
- 자모 크기는 값 1에서 ±15%까지, 값 2에서 ±30%까지 바꾼다. 자모는 다른 자모를 향한 변을 고정하고 바깥쪽으로 커진다. 글자 폭은 값 1에서 ±10%까지, 값 2에서 ±20%까지 바꾼다. 중심선을 늘리고 윤곽을 다시 만들므로 펜 굵기는 변하지 않는다.
- 보정 뒤에 자모 사이의 잉크 간격이 배치가 지키는 간격보다 작으면 보정량을 절반으로 줄인다. 세 번 실패하면 그 자모는 보정하지 않는다.
- 크기는 펜 중심선 기준으로 잰다. 조합은 펜 굵기를 바꿔서 배치를 여러 번 다시 하기 때문이다.
- 통째로 쓴 음절에도 다이얼을 적용한다. 다이얼이 0보다 크면 쓴 배치의 묶음을 풀고 자모마다 보정한다.
- 보정 배율(`visualCalibrationScale`)과 단독 자모의 기준 `가`는 다이얼을 반영하지 않는다. 다이얼을 움직여도 음절이 아닌 글리프는 변하지 않는다.
- 쓰기 화면의 가이드에는 다이얼을 적용하지 않는다.
- 다이얼은 미리보기(`/preview`)의 입력 영역 아래에 둔다. 전체 슬라이더는 4개를 같은 값으로 정한다. 한글 음절 정규화(기본값 0.8)는 전체 슬라이더에 넣지 않고 `/edit`에 둔다. 성격이 기본 보정이고 0이 "쓴 그대로"가 아니기 때문이다.
- 미리보기의 글자는 워커가 입력한 음절만 조합한 작은 OTF로 그린다(`live-font.worker.ts`). 한 번에 요청 하나만 처리하고, 기다리는 요청은 가장 새것만 남긴다.
- 예시 문장 줄은 제거했다. 변경 안내는 다이얼 아래로 옮겼다.
- 입력 영역에서 글자를 선택하면 원본 필기 팝오버가 열린다. 페이지를 열면 첫 두 글자가 선택된 것처럼 강조한다. 실제 포커스는 주지 않는다. 태블릿에서 화면 키보드가 열리기 때문이다.

## Consequences

- 다이얼이 0보다 크면 조합이 약 1.2배 느리다(Node, 3,724자에서 음절당 5.1 ms와 6.3 ms). 폰트 생성 시간도 그만큼 늘어난다. 처음에는 2.2배였다. 줄인 방법은 `docs/performance.md`에 있다.
- 목표 학습은 약 0.6초다. 다이얼이 0이면 실행하지 않는다.
- 다이얼 한 단계의 반영 시간은 기본 문장에서 35에서 45 ms다(dev 모드, 다이얼 켬). 글자가 많으면 더 길다.
- 한도 안에서 글자 하나의 변화는 작다. 효과는 문장에서 보인다. 모든 다이얼이 1일 때 편차는 초성 5.9%, 중성 4.9%, 종성 5.8%, 폭 6.8%다.
- 기본값이 1이므로 새 프로젝트와 이전 프로젝트의 폰트 출력이 바뀐다. 다이얼이 없던 때의 폰트를 가진 프로젝트는 불러올 때 "변경됨"으로 표시한다.
- 펜 크기를 찾는 조합 단계는 다이얼을 초안으로 적용한다. 윤곽을 다시 만들지 않고 늘리기만 한다. 마지막 단계만 펜으로 다시 그린다. 그래서 펜 굵기에 1% 이하의 오차가 생길 수 있다.
- 이전 프로젝트에는 새 키가 없다. 불러올 때 기본 설정과 합친다. 저장 형식 버전은 올리지 않는다.
- 미리보기는 OTF 파일보다 새 값을 보여 줄 수 있다. 파일은 변경 적용 뒤에 바뀐다.
- 기존 배율 3개는 그대로 두었다. 거의 동작하지 않는 문제는 남아 있다.

## Alternatives

- 음절별 학습 비율과 그룹 비율 사이를 보간한다. 음절별 비율은 통째로 쓴 19자에만 있어서 나머지 글자가 변하지 않는다.
- 같은 자모끼리의 평균을 목표로 한다. 자모 고유의 크기 차이는 남지만 그룹 안 편차가 7.3%에서 6.2%로만 줄었다.
- 최종 윤곽을 가로로 늘린다. 세로 획 굵기가 같이 변해서 펜 굵기 규칙과 어긋난다.
- 다이얼을 `/edit`에 둔다. 사용자가 쓴 문장에서 결과를 바로 볼 수 없다.
- 미리보기 글자를 Canvas나 SVG로 직접 그린다. 입력 칸의 커서, 한글 입력, 줄바꿈을 다시 만들어야 한다.
- 메인 스레드에서 조합한다. 기본 문장에서 한 단계에 42 ms 이상이어서 슬라이더가 끊긴다.
