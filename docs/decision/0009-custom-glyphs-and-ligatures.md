# 0009 직접 쓴 글자와 합자

## Context

- 자동 조합 글자가 마음에 들지 않을 때 사용자가 고칠 방법이 없다.
- 폰트에 없는 글자(예: ♡)를 추가할 방법이 없다.
- 글자열(예: ㅋㅋ)을 직접 쓴 한 글자로 바꿀 방법이 없다.

## Decision

- 세 경우를 하나의 개념인 "직접 쓴 글자"로 다룬다. 글자 입력 하나로 시스템이 종류를 정한다.
  - 한 글자이고 폰트가 이미 만드는 글자: 대체. 자동 조합 글자 대신 직접 쓴 글자를 넣는다.
  - 한 글자이고 폰트에 없는 글자: 추가.
  - 2자에서 4자: 합자.
- 직접 쓴 글자는 자모로 나누지 않는다. 칸에 쓴 획을 그대로 윤곽선으로 만든다.
- 프로젝트는 `customGlyphs`에 글자별로 하나씩 저장한다. IndexedDB에서는 글자마다 별도 레코드(`custom:`)이다.
- 합자는 OTF의 GSUB `liga` 표로 만든다. 합자 글자는 사설 영역 코드 포인트(U+E000부터)에 둔다. 글자열 순서로 코드 포인트를 정한다.
- 긴 글자열이 짧은 글자열보다 먼저 일치하도록 긴 것부터 표에 넣는다.
- 변경 여부는 글자별 `updatedAt`으로 비교한다. 복원된 프로젝트는 같은 글자를 다른 객체로 가지기 때문이다.
- 편집 화면에 "직접 쓴 글자" 모드를 둔다. 폰트를 처음 만든 뒤 미리보기에서 3단계 안내를 한 번 보여 준다.

## Consequences

- 합자는 `liga`를 지원하지 않는 앱(예: 일부 워드프로세서)에서 작동하지 않는다.
- 합자의 글자열 글자가 폰트에 없으면 그 합자는 표에 들어가지 않는다.
- 직접 쓴 글자는 크기 보정과 조합 설정의 영향을 받지 않는다. 변경 적용 후에 OTF에 반영된다.
- 저장 형식에 선택 필드가 늘었다. `SCHEMA_VERSION`은 바꾸지 않는다. 이전 프로젝트는 빈 값으로 열린다.

## Alternatives

- 쓰기 페이지에 문장을 더하는 안: 수집 로직과 섞이고 성능 규칙에 영향을 준다. 채택하지 않았다.
- 합자 없이 대체와 추가만 두는 안: 요청의 한 축이 빠진다. 채택하지 않았다.
- 합자를 별도 화면으로 두는 안: 사용자가 방식을 먼저 골라야 한다. 채택하지 않았다.
