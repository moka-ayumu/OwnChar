# UC-05 폰트를 생성한다

- **액터**: 사용자
- **화면**: 쓰기(`/write`), 생성(`/generate`)
- **사전 조건**: 사용자가 자모를 1개 이상 수집했습니다. 모든 필수 항목을 수집하지 않아도 생성할 수 있습니다.

## 기본 흐름

1. 사용자가 **폰트 만들기** 버튼을 누릅니다. 이 버튼은 마지막 문장에 표시됩니다.
2. 다른 문장에서는 **지금 폰트 만들기** 버튼을 사용합니다.
3. 필수 항목이 모두 수집되었고 충돌하는 보정값이 없으면, 시스템이 생성 화면(`/generate`)을 엽니다.
4. 시스템이 백그라운드 worker를 시작합니다.
5. 시스템이 진행률(0에서 100까지)과 현재 단계의 메시지를 표시합니다.
6. 메시지는 다음 순서로 바뀝니다.
   1. 글자 데이터를 준비하고 있어요
   2. 영문과 숫자를 정리하고 있어요
   3. `N / 11,172 글자 조합 중`
   4. OTF 파일을 마무리하고 있어요
7. 시스템이 현대 한글 11,172자와 영문, 숫자, 기호를 조합합니다. CPU 코어가 2개 이상이면 시스템이 최대 4개의 보조 worker로 한글 조합을 병렬 실행합니다.
8. 생성이 끝나면 시스템이 폰트를 저장하고 모든 "변경됨" 표시를 지웁니다.
9. 시스템이 미리보기(`/preview`)를 엽니다. 이후 흐름은 UC-06입니다.

## 대안 흐름 A: 수집하지 않은 글자가 있음

1. 시스템이 "아직 수집하지 않은 글자가 있어요" 대화상자를 표시합니다.
2. 대화상자는 비어 있는 항목의 개수를 종류별로 표시합니다. 종류는 기본 글자, 문맥형, 기호입니다.
3. 대화상자는 비어 있는 글자의 목록도 표시합니다.
4. 시스템은 비어 있는 항목을 다음과 같이 처리합니다.

| 종류 | 처리 |
|------|------|
| 기호 | 폰트에 포함하지 않습니다 |
| 기본 글자 | 폰트에 포함하지 않습니다 |
| 문맥형 | 이미 쓴 다른 문맥의 같은 자모로 대체합니다 |

5. 사용자가 **계속 작성하기**를 누르면 대화상자가 닫히고 쓰기가 계속됩니다.
6. 사용자가 **그래도 생성하기**를 누르면 생성이 시작됩니다. 충돌하는 보정값이 있으면 대안 흐름 B로 진행합니다.

## 대안 흐름 B: 기존 보정값과 충돌함

- **조건**: 필기를 변경했고, 고급 편집(UC-07)에서 보정한 글리프가 있습니다.

1. 시스템이 "기존 글리프 보정을 어떻게 할까요?" 대화상자를 표시합니다.
2. 대화상자는 보정한 글리프의 개수를 표시합니다.
3. 사용자가 다음 중 하나를 선택합니다.

| 선택 | 결과 |
|------|------|
| 보정 유지하고 재합성 | 보정값을 유지한 채 생성합니다. 결과가 달라질 수 있습니다 |
| 기존 보정 삭제 후 재합성 | 모든 보정값과 편집 기록을 삭제한 뒤 생성합니다 |
| 취소 | 대화상자가 닫히고 아무 변화도 없습니다 |

## 대안 흐름 C: 생성 취소

1. 생성 중에 사용자가 **생성 취소**를 누릅니다.
2. 시스템이 worker를 중지합니다.
3. 시스템이 프로젝트 상태를 `writing`으로 되돌립니다.
4. 시스템이 쓰기 화면(`/write`)을 엽니다. 쓴 내용은 그대로 유지됩니다.

## 대안 흐름 D: 생성 실패

1. worker가 오류를 보고하거나 시작하지 못합니다.
2. 시스템이 "생성 중 문제가 발생했습니다"와 오류 메시지를 표시합니다.
3. 사용자가 **다시 시도**를 누릅니다.
4. 시스템이 처음부터 생성을 다시 실행합니다.

## 사후 조건

- 성공하면 시스템이 OTF 데이터를 프로젝트에 저장합니다. 프로젝트 상태는 `ready`입니다.
- 취소하면 이전에 생성한 폰트는 변하지 않습니다.
- 실패하면 새 폰트는 저장되지 않습니다. 이전에 생성한 폰트는 변하지 않습니다.
